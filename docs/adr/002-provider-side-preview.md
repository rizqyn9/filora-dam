# ADR-002: Provider-Side Preview for Images Only

Image previews (thumbnails) are generated by the storage provider via URL transforms, not by our server.

---

## Status

Accepted

## Context

Filora accepts any file type. Users expect visual previews when browsing image
assets. Preview generation options:

1. **Server-side** — API generates thumbnails before/after upload using ffmpeg,
   ImageMagick, etc. Requires compute resources, adds upload latency, and
   introduces binary dependencies.
2. **Provider-side** — Cloudinary and ImageKit offer on-the-fly image
   transformation via URL parameters (resize, crop, format conversion). Free
   within their quota. Zero compute on our side.
3. **Hybrid** — provider transforms where available, server-side fallback for
   providers without transform support (R2, GCS).

## Decision

Use provider-side URL transforms for image previews. Non-image files (PDF,
video, archives, documents) display a static icon based on MIME type — no
preview generation.

### Scope

- **Images** (JPEG, PNG, WebP, GIF, etc.): thumbnail via provider URL transform.
- **Everything else**: file-type icon. No server-side rendering.

### Why not video thumbnails?

Video frame extraction requires ffmpeg and significant compute. For a family
archive with free-tier infra, the complexity-to-value ratio is too high for MVP.
Backlog candidate.

## Consequences

**Positive:**
- Zero compute cost for previews.
- No binary dependencies (ffmpeg, ImageMagick) in the API.
- Instant — no processing queue or latency.
- Works within provider free-tier quotas (transforms count against bandwidth, not
  storage).

**Negative:**
- Preview only works for images on providers that support URL transforms
  (Cloudinary, ImageKit). Files stored on R2/GCS get no preview.
- Non-image files have no visual preview (acceptable — matches user expectation
  for a file manager).

**Mitigation for R2/GCS:**
- For MVP, R2/GCS is primarily the archive layer (not the serving layer for
  browsing). Serving layer defaults to Cloudinary/ImageKit which support
  transforms.
- If R2 is used as serving layer, images display without thumbnail resize (full
  URL, browser does the scaling). Acceptable for MVP.
